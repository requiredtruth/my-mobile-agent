# My Mobile Agent 1.0 specification

- Local llama.cpp CPU inference from single-file GGUF models. ARM64 and x86_64, Android 8+. Mapped weights, configurable 2K–32K context, up to four CPU threads. Embedded supported chat templates. Explicit errors for context overflow, unsupported models and insufficient memory.
- Curated downloadable GGUF catalog, including Spark-X2.5 1.7B and 4B. Publisher links, quantization, byte sizes and download actions. GitHub release-asset discovery, direct HTTPS URLs and file imports. Android Download Manager provides persistent progress, cancellation, failure states and completion. Downloaded models can be loaded or deleted. Header validation rejects HTML and LFS pointers.
- SQLite WAL multi-conversation chat. User, assistant, tool and error chunks display separately. Streaming response, stop controls, partial responses saved on stop. Foreground service and wake lock for inference, within Android platform restrictions.
- Individual system instruction fragments with names, enabled state, edit/delete and explicit order. Enabled instructions compile at each turn.
- Independent 4096-dimensional bipolar hypercubes used **only for retrieval-augmented generation**. Deterministic token-vector bundling, packed coordinates, Hamming similarity, overlapping document passages. Disk caches page groups of 64 passages; only two groups resident. Source text remains in SQLite. No Q-Manifold code, application components, training machinery or checkpoints are copied or imported.
- Automatic RAG uses the question and recent user turns from the current conversation. Retrieved source names, passage IDs, scores and text appear in tool cards. Explicit knowledge.search(query) lets the model retrieve further passages.
- History is separate from knowledge. Past-chat content is supplied only when the model requests conversations.search(query), followed by conversations.summary(conversation,message). Search returns up to 12 hits with IDs and excerpts; summary reads up to seven neighboring messages with bounded extractive text. No automatic injection of other conversations.
- Model-native chat templates and output parsers, including Spark-X2.5 implicit `<think>` prefixes and GLM-style `<tool_call>/<arg_key>/<arg_value>` calls. Native tool schemas, IDs and tool-role results round-trip through the template. Strict JSON fallback remains available. Only complete stopped requests execute, with validated names/arguments, duplicate suppression and at most six calls before a final-answer pass. Requests and results display separately.
- Thinking off by default through `enable_thinking=false`; optional 128/256-token thinking budgets close the template reasoning channel when exhausted. Reasoning is stored separately in collapsed cards and excluded from speech and future answer context. Answers default to 1536 tokens, configurable to 768/3072. Prompt token accounting trims complete old turns while preserving system instructions and the latest question/tool chain; output length and truncation are explicit. A bounded direct-answer retry handles empty reasoning-only responses. Tool reliability remains model-dependent.
- Android speech recognizer input fills the composer for review, offline preference requested. Android TTS supports manual speak/stop and optional automatic speech. Provider availability, languages and provider network use are device-dependent.
- Knowledge imports: UTF-8 text, up to 8 MiB per document, plus manual text. No cloud inference API, no model keys required, Android backups disabled.
- Verification: standalone hypercube ranking/determinism/cache tests; Android storage/history/tool/instruction/RAG tests and native GGUF generation smoke test; release compilation/lint, signature and 16 KiB alignment verification.
- Main pushes publish versioned releases only after checks pass, containing APK, source.zip, spec.md and SHA256SUMS. CI preserves signing identity through a cache; later updates block if the original key is missing.
